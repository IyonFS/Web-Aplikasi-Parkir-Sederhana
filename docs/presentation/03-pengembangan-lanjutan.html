Progress Pengembangan

Hygiopark dibangun bertahap dari pondasi dasar menuju sistem parkir yang semakin pintar.

Dari struktur kode yang ada, terlihat bahwa project ini berkembang secara bertahap: dimulai dari autentikasi, data master, modul slot dan reservasi, lalu ditambah payment gateway, audit log, real-time, waitlist, dan recurring booking.

Halaman ini penting untuk menunjukkan bahwa project tidak dibuat sekaligus, melainkan tumbuh secara logis dari kebutuhan dasar menuju fitur yang lebih kompleks dan realistis.

Alur Pengerjaan yang Sudah Dilalui

Urutan berikut membantu menjelaskan bahwa aplikasi tumbuh dari modul inti ke modul lanjutan. Penjelasan ini biasanya memudahkan audiens memahami prioritas pengerjaan dan alasan urutan implementasi fitur.

01

Menyiapkan pondasi project

Frontend dan backend dipisah, lalu ditambahkan package, Vite, Express, Prisma, dan environment file.

02

Membuat autentikasi dan role

Login, register, proteksi route, refresh token, dan pembagian akses admin, operator, serta user.

03

Menyusun data master parkir

Area parkir, slot parkir, tarif, kendaraan, dan user management dibangun untuk kebutuhan operasional.

04

Membangun alur reservasi utama

User dapat memilih slot, menentukan waktu, melihat status, membatalkan, memperpanjang, dan mengakses QR ticket.

05

Menambahkan pembayaran

Payment dibuat dengan mode demo dan integrasi Midtrans agar aplikasi bisa dipresentasikan maupun dikembangkan lebih jauh.

06

Menambahkan fitur cerdas

Waitlist, recurring booking, notifikasi, dan scheduler membuat alur parkir lebih otomatis dan realistis.

07

Merapikan monitoring dan dokumentasi

Analytics, audit log, struktur folder, dan dokumen presentasi disiapkan agar project mudah dijelaskan.

Rencana Lanjutan

Fitur yang Layak Dilanjutkan

Scan QR di gerbang masuk/keluar Reservasi bisa diverifikasi otomatis saat kendaraan datang.
Riwayat transaksi lebih lengkap Termasuk filter periode, ekspor PDF/Excel, dan cetak laporan.
Peta slot yang lebih visual Denah interaktif per lantai agar operator cepat membaca kondisi parkir.
Push notification atau email Untuk reminder booking, antrean waitlist, dan status pembayaran.
Multi-cabang atau multi-gedung Agar satu sistem dapat mengelola beberapa lokasi sekaligus.
Testing otomatis Unit test dan integration test agar perubahan fitur lebih aman.
Catatan Teknis

Perbaikan yang Disarankan

Dokumentasi arsitektur Bisa ditambah diagram alur request, modul, dan API flow.
Optimasi validasi form Error feedback di frontend masih bisa dibuat lebih detail dan lebih jelas.
Audit akses operator Role operator bisa diperdalam jika hak akses perlu dibuat lebih spesifik.
Hardening produksi Logging, monitoring error, backup database, dan manajemen secret perlu diperketat.

Arah Pengembangan yang Paling Masuk Akal

Untuk Pengguna

Reservasi lebih cepat Menyimpan kendaraan favorit, jam favorit, dan tombol pesan ulang.
Status parkir lebih jelas Menampilkan progres dari booking, pembayaran, hingga parkir selesai.
Notifikasi yang konsisten Reminder sebelum booking dimulai atau saat slot waitlist tersedia.

Untuk Admin dan Operator

Monitoring lebih rinci Heatmap slot sibuk, pendapatan per area, dan performa operator.
Audit dan keamanan Log aktivitas yang lebih rinci serta kontrol role yang lebih tersegmentasi.
Automasi operasional Pengingat perawatan slot, laporan otomatis, dan backup terjadwal.

Bug atau Risiko yang Masih Perlu Diperhatikan

Risiko Operasional
Port backend bisa berubah otomatis Jika port 4000 dipakai, backend pindah ke port lain dan frontend bisa salah target jika env belum disesuaikan.
Scheduler bergantung pada proses backend Fitur recurring dan expiry waitlist hanya berjalan jika server backend terus aktif.
Integrasi Midtrans bergantung pada env Jika key atau callback belum benar, pembayaran bisa tetap berjalan di mode demo atau status tidak sinkron.
Risiko Pengembangan
File demo lama masih ada backend/data/db.js menunjukkan versi in-memory lama dan bisa membingungkan bila tidak dijelaskan.
Belum terlihat suite test otomatis Modul reservasi, payment, waitlist, dan recurring lebih berisiko saat diubah.
Perbedaan mode lokal dan produksi Build, env, dan layanan eksternal bisa menimbulkan bug yang tidak muncul saat demo lokal sederhana.

Cara Menjelaskan Halaman Ini Saat Presentasi

Jika ingin presentasi terasa runtut, jelaskan dulu bahwa fitur dasar seperti auth, slot, dan reservasi adalah pondasi. Setelah itu baru tunjukkan bahwa payment, waitlist, recurring, dan analytics merupakan lapisan lanjutan yang menambah nilai praktis dan nilai inovasi pada aplikasi.
