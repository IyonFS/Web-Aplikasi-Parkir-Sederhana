Portabilitas Aplikasi

Hygiopark cukup siap dijalankan di perangkat lain selama environment dan database ikut disiapkan.

Project ini sudah memiliki .env.example, package.json, lockfile dependency, schema Prisma, seed data, dan konfigurasi deploy. Artinya source code aman dipindah ke laptop lain atau repository Git.

Tantangan utamanya bukan pada isi source code, tetapi pada konsistensi environment: URL database, secret key, callback payment, dan sinkronisasi port frontend-backend harus tetap benar setelah dipindahkan.

Karena itu, halaman ini tidak hanya menjelaskan perintah terminal, tetapi juga apa saja yang harus disiapkan sebelum mulai, urutan setup yang aman, dan cara memeriksa apakah aplikasi benar-benar siap dipakai.

Sudah Siap

Checklist Kesiapan

Ada backend/.env.example dan frontend/.env.example sebagai template konfigurasi.
Dependency sudah terdokumentasi di backend/package.json dan frontend/package.json.
Schema dan seed database tersedia di folder backend/prisma/.
Frontend dan backend terpisah jelas sehingga setup ulang lebih mudah.
Deploy dasar sudah dipersiapkan melalui Docker, Nginx, dan PM2.

Sebelum membuka terminal, pastikan perangkat tujuan sudah siap secara alat, software, dan konfigurasi. Persiapan ini penting karena sebagian besar error awal biasanya muncul bukan dari source code, tetapi dari dependency yang belum lengkap, database yang belum aktif, atau file environment yang belum benar.

Cara Menjalankan di Perangkat Lain

Urutan setup paling aman adalah menyiapkan environment, menginstall dependency, menyalakan database, menjalankan migrasi schema, mengisi seed, lalu baru menyalakan backend dan frontend. Dengan urutan ini, error biasanya lebih mudah dilacak karena penyebabnya tidak tercampur.

Langkah Umum

  1. Clone repository atau salin folder project lengkap ke perangkat tujuan.
  2. Pastikan Node.js sudah terinstall, lalu cek dengan node -v dan npm -v.
  3. Siapkan PostgreSQL lokal atau jalankan container database lewat Docker.
  4. Masuk ke folder backend lalu salin .env.example menjadi .env.
  5. Masuk ke folder frontend lalu salin .env.example menjadi .env.local.
  6. Isi variabel penting seperti DATABASE_URL, JWT_SECRET, FRONTEND_URL, dan VITE_API_URL.
  7. Install dependency backend dengan npm install, lalu lakukan prisma generate, migrasi, dan seed.
  8. Install dependency frontend dengan npm install, lalu jalankan server frontend.
  9. Start backend terlebih dahulu, baru frontend, agar API sudah siap saat halaman dibuka.
  10. Buka frontend di browser, login dengan akun demo, lalu uji alur slot, reservasi, dan dashboard.

Urutan Menjalankan yang Paling Aman

01

Cek versi dan alat

Pastikan Node.js, npm, dan PostgreSQL atau Docker benar-benar tersedia. Jika alat dasar belum siap, langkah berikutnya akan gagal.

02

Siapkan file environment

Backend dan frontend harus punya file env sendiri. Jangan jalankan project sebelum variabel dasar seperti URL database dan secret key diisi.

03

Aktifkan database

Hygiopark bergantung pada PostgreSQL. Jika database belum hidup, migrasi dan seed tidak akan jalan.

04

Install dependency backend

Backend perlu package seperti Express, Prisma, JWT, bcrypt, dan Socket.IO sebelum server bisa dijalankan.

05

Generate, migrate, dan seed database

Langkah ini membuat struktur tabel dan mengisi data demo seperti akun, lot, slot, reservasi, dan payment.

06

Jalankan backend

Setelah backend aktif, baru frontend punya target API yang bisa dipanggil untuk login dan mengambil data.

07

Install dan jalankan frontend

Frontend React/Vite menampilkan halaman dan menghubungkan user ke API backend.

08

Lakukan pengecekan hasil

Uji login akun demo, buka dashboard, cek slot, dan lakukan satu reservasi agar setup benar-benar tervalidasi.

Perintah Terminal yang Berguna

Cek Alat di Perangkat Baru

node -v
npm -v
docker -v
docker compose version

Jalankan ini lebih dulu untuk memastikan Node.js, npm, dan Docker memang tersedia sebelum setup project dimulai.

Masuk ke Folder Project

cd path\\ke\\smart-parking
dir
cd backend

Berguna setelah project dipindah lewat ZIP agar terminal benar-benar bekerja dari folder project yang tepat.

Backend

cd backend
copy .env.example .env
npm install
npx prisma generate
npx prisma migrate dev --name init
node prisma/seed.js
npm run dev

Backend default berjalan di http://localhost:4000, tetapi dapat pindah port otomatis jika 4000 sudah dipakai.

Frontend

cd frontend
copy .env.example .env.local
npm install
npm run dev

Frontend default berjalan di http://localhost:5173.

Database dengan Docker

cd ..
docker compose up -d postgres
docker compose ps

Cocok dipakai jika PostgreSQL belum terpasang langsung di sistem.

Perintah Tambahan

cd backend
npm run db:generate
npm run db:migrate
npm run db:seed
npm run db:studio
npm run midtrans:check

Perintah ini membantu validasi database, seed ulang, dan pengecekan konfigurasi payment.

Jika Folder Baru Dipindah dari ZIP

cd backend
copy .env.example .env
npm install
cd ..\\frontend
copy .env.example .env.local
npm install

Ini adalah setup minimum yang hampir selalu dibutuhkan di perangkat baru karena file env dan dependency biasanya tidak ikut siap pakai.

Build Ulang Frontend Jika Perlu

cd frontend
npm run build
npm run preview

Pakai ini jika ingin memastikan folder build bisa dibuat ulang dan frontend siap dipreview tanpa development mode.

Cek Port dan Koneksi Dasar

curl http://localhost:4000/api/health
curl http://localhost:5173
netstat -ano | findstr :4000
netstat -ano | findstr :5173

Berguna untuk memastikan backend dan frontend benar-benar hidup, serta untuk mengecek apakah ada konflik port di perangkat tujuan.

Jika Terjadi Error Saat Menjalankan

Error yang Sering Muncul

Database connection failed biasanya berarti PostgreSQL belum hidup atau DATABASE_URL salah.
Module not found biasanya karena npm install belum dijalankan di folder yang benar.
Prisma client not generated biasanya perlu npx prisma generate.
Port already in use berarti port 4000 atau 5173 sudah dipakai proses lain.
Frontend gagal fetch API biasanya karena URL backend di env frontend belum cocok.

Cara Melacaknya

Baca error dari terminal backend dan frontend secara terpisah agar sumber masalah lebih jelas.
Cek apakah file env sudah dibuat dari contoh dan tidak ada variabel penting yang kosong.
Pastikan database sudah berisi tabel hasil migrasi, bukan hanya server PostgreSQL yang aktif.
Gunakan akun demo bawaan setelah seed selesai untuk memastikan data awal sudah masuk.
Jika payment belum dipakai, fokus dulu memastikan login, dashboard, slot, dan reservasi dasar berhasil.

Hal yang Perlu Dicek Setelah Setup

Pemeriksaan Dasar

Pastikan backend dapat terhubung ke PostgreSQL tanpa error.
Pastikan frontend mengarah ke URL API yang benar melalui file env.
Cek apakah login akun demo berhasil dan dashboard terbuka.
Uji satu alur reservasi sampai data muncul di halaman reservasi.

Pemeriksaan Lanjutan

Jika memakai Midtrans, pastikan mode sandbox atau production sesuai env.
Jika memakai real-time, cek update slot saat aplikasi dibuka di dua tab.
Jika backend pindah port otomatis, sesuaikan URL frontend agar koneksi tidak gagal.
Jika deploy, cek juga Nginx, Docker, PM2, dan file build frontend.

Kalau bagian ini ingin dipresentasikan singkat, cukup tekankan bahwa source code sudah portable, sedangkan proses setup tetap butuh ketelitian pada environment dan layanan pihak ketiga.
